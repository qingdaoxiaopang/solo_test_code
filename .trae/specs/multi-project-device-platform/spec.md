# 多项目设备安装运维平台规格说明书

## 一、技术要求

### 1. 技术架构概述

本平台采用前后端分离架构，后端使用Java 17 + Spring Boot 3.5.x，前端支持多终端访问：PC端（Vue 3 + Element Plus）、移动端Web（Vue 3 + Vant）、微信小程序（UniApp）。系统包含四大核心模块：系统管理、项目管理、业务配置、设备管理。使用Redis作为缓存中间件，MinIO负责对象存储。

### 2. 后端技术栈

| 技术项 | 技术选型 | 说明 |
|--------|----------|------|
| 运行环境 | Java 17 | LTS版本 |
| 框架 | Spring Boot 3.5.x | 最新稳定版本 |
| 数据库 | PostgreSQL 13.x+ | 企业级关系型数据库 |
| 缓存 | Redis 6.x+ | 高性能键值对存储，用于缓存、会话等 |
| 对象存储 | MinIO | 高性能对象存储，用于存储文件、图片、视频等 |
| ORM | MyBatis-Plus | 强大的CRUD和分页功能 |
| ID生成器 | 雪花算法 | 分布式ID生成 |
| 认证框架 | Sa-Token | 轻量级权限认证，支持Token认证、会话管理、路由拦截 |
| API文档 | Swagger/OpenAPI 3.0 | 接口文档自动生成 |
| API风格 | RESTful API | 统一接口规范 |

### 5. Redis缓存使用场景

| 使用场景 | 说明 |
|---------|------|
| 会话管理 | 存储用户登录Token和会话信息 |
| 字典数据缓存 | 缓存系统字典数据，避免频繁查询数据库 |
| 首页仪表盘数据 | 缓存统计数据，提升页面响应速度 |
| 热点数据缓存 | 缓存频繁访问的设备信息、项目信息等 |
| 分布式锁 | 用于防止重复提交、资源竞争等场景 |
| 接口限流 | 基于Redis实现接口访问频率限制 |

### 11. 安全要求

- Sa-Token认证框架，Token会话管理
- 密码加密存储（BCrypt）
- SQL注入防护
- XSS攻击防护
- CORS跨域配置
- 接口访问频率限制（基于Redis实现）
- 敏感操作日志记录
- 文件上传安全验证（类型、大小、内容检查）
- MinIO访问权限控制

### 12. 性能要求

- 接口响应时间 < 200ms（不含文件上传）
- 支持1000+设备数据管理
- 支持100+并发用户
- 支持移动端离线缓存（本地存储）
- Redis缓存提升热点数据访问速度
- MinIO大文件分片上传支持

### 16. Headless API支持

#### 16.1 认证方式

后端接口支持多种认证方式，满足不同客户端的需求：

| 认证方式 | 说明 | 适用场景 |
|---------|------|---------|
| Sa-Token Session | 传统Session认证 | PC端、移动端Web |
| Bearer Token | 无状态Token认证 | 小程序、移动App、第三方集成 |
| API Key | API密钥认证 | 服务端集成、自动化脚本 |

#### 16.2 Bearer Token认证

- Token格式：`Bearer <token>`
- Token放置位置：HTTP请求头 `Authorization`
- Token有效期：可配置，默认7天
- Token刷新：支持刷新Token机制

#### 16.3 API Key认证

- API Key放置位置：HTTP请求头 `X-API-Key`
- API Key与Secret配对使用：`X-API-Secret`
- API Key管理：支持在系统管理中创建、禁用、删除API Key
- 权限控制：API Key可配置访问权限范围

#### 16.4 API版本控制

- 版本标识方式：URL路径 `/api/v1/`
- 支持版本：`v1`（当前版本）
- 向后兼容：新版本发布后，旧版本API保持可用

#### 16.5 无状态设计

- 接口不依赖Session状态
- 每次请求独立认证
- 支持水平扩展部署

#### 16.6 限流控制

| 限流类型 | 说明 | 限制策略 |
|---------|------|---------|
| 接口限流 | 单接口访问频率限制 | 基于IP或用户，每分钟最大请求数 |
| 用户限流 | 用户级别总请求限制 | 基于用户ID，每小时最大请求数 |
| IP限流 | IP地址级别限制 | 基于客户端IP，每分钟最大请求数 |

#### 16.7 Headless API端点

所有业务接口均支持headless访问，端点前缀为 `/api/v1/`

#### 16.8 响应格式

统一JSON响应格式，不返回HTML或视图：

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": 1620000000000
}
```

#### 16.9 CORS配置

支持跨域访问，配置允许的Origin、Method、Header：

| 配置项 | 值 |
|-------|-----|
| 允许Origin | *（生产环境可配置具体域名） |
| 允许Method | GET, POST, PUT, DELETE, OPTIONS |
| 允许Header | Content-Type, Authorization, X-API-Key, X-API-Secret |
| 允许Credentials | true |

#### 16.10 安全要求

- API Key需妥善保管，避免泄露
- Token传输需使用HTTPS
- 敏感接口需额外校验
- 日志记录API调用行为
