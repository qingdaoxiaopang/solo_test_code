# 数据库设计规范

## 1. 基本设计原则

### 1.1 范式设计

- 遵循第三范式（3NF）设计
- 避免数据冗余
- 确保数据一致性

### 1.2 模块化设计

- 按业务模块划分表：`sys_*`系统、`prj_*`项目、`dev_*`设备、`ins_*`安装、`opr_*`运维
- 模块之间依赖清晰

### 1.3 扩展性

- 预留扩展字段：`ext1`、`ext2`、`ext_json`（JSON类型，可选）
- 使用字典管理状态和类型

## 2. 表命名规范

### 2.1 表名

- 表名使用小写下划线分隔：`sys_user`、`prj_project`
- 表名前缀按模块：
  - `sys_`：系统管理
  - `prj_`：项目管理
  - `dev_`：设备管理
  - `ins_`：安装管理
  - `opr_`：运维管理

### 2.2 字段名

- 字段名使用小写下划线分隔：`user_name`、`create_time`
- 避免使用数据库关键字作为字段名

## 3. 字段设计规范

### 3.1 主键

- 统一使用`id`作为主键名
- 使用BIGINT类型（64位），自增：`id BIGINT PRIMARY KEY AUTOINCREMENT`
- 使用雪花ID或UUID策略（可选）

### 3.2 通用字段

每张表必须包含以下字段：

```sql
-- 创建时间
create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP

-- 更新时间
update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
```

### 3.3 布尔类型

- 使用TINYINT（0/1）表示：`status TINYINT NOT NULL DEFAULT 1`
- 1表示启用/是，0表示禁用/否

### 3.4 状态/类型字段

- 使用VARCHAR类型存储枚举值：`status VARCHAR(20) NOT NULL`
- 状态值使用字典管理
- 推荐使用英文单词，如：`ACTIVE`、`INACTIVE`、`PENDING`

### 3.5 时间字段

- 统一使用DATETIME类型
- 时间字段命名：`*_time`、`*_date`
- 精度到秒级别

### 3.6 金额/数字

- 金额使用DECIMAL(10,2)类型：`price DECIMAL(10,2) NOT NULL DEFAULT 0`
- 数量使用INT/BIGINT

### 3.7 文本字段

- 短文本（<255）：VARCHAR
- 长文本（>=255）：TEXT
- 大文本：使用CLOB或单独的文件存储

### 3.8 关联字段

- 外键字段命名：`{表名}_id`，如：`project_id`、`user_id`
- 不强制创建物理外键，使用逻辑外键
- 逻辑外键需要添加索引

### 3.9 软删除

- 使用`deleted`字段表示逻辑删除：`deleted TINYINT NOT NULL DEFAULT 0`
- 0表示未删除，1表示已删除
- 查询时过滤已删除记录

## 4. 索引设计规范

### 4.1 主键索引

- 主键自动创建索引

### 4.2 唯一索引

- 业务唯一字段创建唯一索引：`username`、`code`
- 多字段组合唯一索引

### 4.3 普通索引

- 查询条件字段添加索引：`project_id`、`status`
- 排序字段添加索引
- 多字段索引遵循最左前缀原则

### 4.4 索引命名

- 唯一索引：`uk_字段名1_字段名2`
- 普通索引：`idx_字段名1_字段名2`

## 5. 字符集和排序规则

- 数据库字符集使用`UTF-8`或`UTF-8MB4`
- SQLite默认使用UTF-8

## 6. 数据库初始化脚本

### 6.1 脚本规范

- 文件名格式：`V{版本号}__{描述}.sql`
- 版本号使用时间戳格式：`V202401010001__init_tables.sql`

### 6.2 脚本内容

- DDL语句：建表、建索引
- 初始化数据：字典数据、默认用户等
- 注释说明：表和字段注释

## 7. 各模块表设计要点

### 7.1 系统模块

- 用户表：密码必须加密存储
- 角色权限：多对多关系
- 操作日志：记录操作人和时间，IP等信息

### 7.2 项目模块

- 项目表：包含负责人、时间范围
- 站点表：支持树形结构，有`parent_id`
- 数据隔离：项目之间完全隔离

### 7.3 设备模块

- 设备表：包含详细的设备信息、状态、位置
- 设备生命周期：独立的事件表记录状态变更
- 设备参数：动态参数使用JSON或关联表存储

### 7.4 安装模块

- 安装任务：有完整的状态流转
- 检查清单：任务关联检查项
- 安装记录：支持附件上传

### 7.5 运维模块

- 工单数：有完整的处理时间线
- 巡检计划：支持周期配置
- 备件管理：库存操作记录要完整

## 8. 性能优化

- 避免使用`SELECT *`查询所有字段
- 使用LIMIT分页
- 大表建立合适的索引
- 使用缓存减轻数据库压力

## 9. 数据安全

- 敏感字段加密存储（如密码）
- 操作日志完整记录
- 定期备份数据
